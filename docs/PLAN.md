# 🗺️ خطة التطوير الاحترافية — منصة Disor للوكلاء

> الهدف: تحويل البوت من "بوت أوامر يدير سيرفر" إلى **وكيل حقيقي كامل** — بحواس خارج ديسكورد، ذاكرة، استقلالية زمنية، وموثوقية لا تتوقف.
>
> قاعدة العمل: **مستوى واحد في كل مرة** — تنفيذ → اختبارات → مراجعة → دفع → ثم فقط الانتقال للتالي. أي تعديل يجب ألا يكسر ما بُني قبله (اختبارات المستويات السابقة تُشغَّل دائماً).

## 🥇 المستوى 1 — الوكيل الحقيقي (الحواس + الذاكرة + الزمن + الموثوقية)

### 1A. 🔍 أدوات ويب حقيقية
| بند | التفاصيل |
|---|---|
| `web_search` | بحث فعلي: DuckDuckGo Lite بدون مفاتيح (افتراضي) + دعم Brave/SerpAPI بمفاتيح ENV إن وُجدت. يرجع {title, url, snippet} |
| `read_url` | جلب صفحة وتنظيف HTML → نص مقروء (عنوان + محتوى حتى 8000 حرف) مع حماية: content-type، حد حجم 2MB، timeout، منع SSRF للعناوين الداخلية |
| الصلاحية | متاحة لـ member (قراءة فقط آمنة) |
| القبول | اختبارات بمحاكاة HTTP + fixtures HTML: تحليل DDG، استخراج نص، رفض غير HTML، قطع الطول |

### 1B. 🧠 ذاكرة طويلة المدى
| بند | التفاصيل |
|---|---|
| التخزين | مجموعة `agent_memories`: {agent_id, guild_id, user_id, kind, content, tags, hits, timestamps} |
| الأدوات | `remember` (يضيف حقيقة، dedup + حد 200/مستخدم)، `recall` (بحث بالكلمات + تعزيز حداثة)، `forget` (حذف بمعرف أو استعلام) |
| الحقن التلقائي | قبل كل محادثة: أعلى 12 ذكرى للمستخدم تُحقن في السياق |
| الصلاحية | member لكنه محصور بذكرياته هو فقط |
| القبول | اختبارات: dedup، الحد الأقصى، ترتيب الصلة، النسيان، عزل المستخدمين |

### 1C. ⏰ محرك تذكيرات
| بند | التفاصيل |
|---|---|
| التخزين | مجموعة `agent_reminders`: {agent_id, guild_id, channel_id, user_id, text, due_at, recurrence} |
| الأدوات | `set_reminder` (بعد-دقائق / وقت-ISO / يومي HH:MM / أسبوعي يوم+وقت)، `list_reminders` (تذكيراته هو)، `cancel_reminder` |
| المحرك | ماسح كل 20 ثانية داخل runtime الوكيل، إرسال بقناة الطلب عبر عميل الوكيل نفسه، إعادة جدولة التكرار، التقاط المفقود عند الإقلاع |
| القبول | اختبارات: كل صيغ الوقت، دورة المحرك بتوقيت وهمي، التكرار، catch-up |

### 1D. 🔄 Fallback بين المزودين
| بند | التفاصيل |
|---|---|
| المنطق | فشل المزود الأساسي (شبكة/RateLimited/حظر) → تجربة المزود التالي في السلسلة تلقائياً لنفس الطلب، جلسة جديدة للمزود البديل، واستكمال بقية خطوات الحلقة به |
| الإعداد | لكل وكيل: `fallback_enabled` + `fallback_chain` (ترتيب) — واجهة في صفحة المزود باللوحة (إضافة/إزالة/تفعيل) والتحقق من جاهزية كل مزود |
| الشفافية | سجل في agent_logs + سطر في الكونسول؛ المستخدم يرى الرد طبيعياً |
| القبول | اختبار: مزود أساسي يفشل → البديل يجيب، ولا يتغير سلوك عدم فشل الأساسي |

### 1E. 🎨 تجديد الأوامر والتصميم
| بند | التفاصيل |
|---|---|
| نظام تصميم موحد | دالة embed مركزية: ألوان دلالية، ترويسة بأيقونة، فوتر باسم الوكيل + وقت، فواصل نصية ثابتة |
| أمر `/مساعدة` | قائمة كاملة مصنفة (محادثة/إدارة/ويب/ذاكرة/تذكير/مزود) بوصف موجز لكل أمر |
| تنظيف الأوصاف | توحيد أسلوب وصف كل أوامر السلاش عربياً، والردود المدمجة (ephemeral) حيث يلزم |
| القبول | مراجعة بصرية للـ embeds عبر اختبار بنية الحقول |

## 🥈 المستوى 2 — النضج ✅ (مكتمل)

> **منجز بالكامل (v7.3.0 "Sentinel")**: صفحة الإعدادات الكاملة (عرض/كشف آمن/تعديل مجزأ + تعطيل web_search)، الشخصية من ملف، قاعدة معرفة RAG بأدوات search_knowledge/list_knowledge، تتبع الاستخدام مع صفحة إحصائيات لكل وكيل، الاستباقية بتهدئة لكل قناة، تشفير AES-256-GCM للتوكنات مع ترحيل شفاف عند الإقلاع. 118 اختباراً (16 E2E + 102 وحدة).

### 2A. ⚙️ صفحة إعدادات الوكيل الكاملة — عرض + تعديل (طلب مباشر)
| بند | التفاصيل |
|---|---|
| المشكلة | لا يمكن رؤية إعدادات وكيل قائم (اسمه/توكنه/توكن نموذجه/مزوده) — الإنشاء فقط |
| الصفحة | `renderAgentSettings`: كل الحقول مع إخفاء الأسرار (`••••1234`) + زر «كشف» يرسل القيمة الحقيقية رسالة ephemeral لا يراها غير طالبها |
| التعديل | نوافذ تعديل مجزأة: الاسم + الشخصية / توكن ديسكورد / بيانات المزود (حقول المزود نفسه) — تُحدث قاعدة البيانات + الـ runtime الحي فوراً |
| تفعيل/تعطيل الأدوات | لكل وكيل: `features.web_search` (افتراضي مفعّل) — لأن كل نموذج أصبح يملك بحثاً مدمجاً، البحث الخارجي قد لا يلزم → يُعطَّل من إعدادات الوكيل |
| القبول | اختبار: الصفحة لا تعرض أي سر خام، زر الكشف يعمل، التبديل يُخزن ويُحدّث حياً، runAgent يرفض web_search عند التعطيل |

### 2B. 📎 الشخصية من ملف (طلب مباشر)
| بند | التفاصيل |
|---|---|
| التدفق | منشن الوكيل + كلمة «شخصية» + إرفاق ملف .txt/.md (≤ 1MB، ≤ 20000 حرف) → يقرأ الملف ويستبدل الشخصية في القاعدة والـ runtime الحي |
| الصلاحية | أدمن/مالك فقط — الأعضاء لا يستطيعون تغيير شخصية الوكيل |
| القبول | اختبار وحدة للتحليل والتحقق (نوع الملف، الحجم، الصلاحية) + تحديث حي |

### 2C. 📚 قاعدة معرفة RAG لكل وكيل
| بند | التفاصيل |
|---|---|
| التخزين | مجموعة `agent_knowledge` (مُعدة في config.js): {agent_id, guild_id, source, chunk_index, content, tokens, created_at} |
| الرفع | من صفحة المعرفة باللوحة: زر «إضافة ملفات» → أرسل الملفات في القناة خلال 3 دقائق → Manager يلتقطها (.txt/.md/.json وغيرها من الامتدادات النصية، ≤ 1MB) |
| التقطيع | تقطيع واعٍ بالفقرات (~900 حرف، تداخل 120) + فهرسة بالكلمات (نفس tokenizer الذاكرة) |
| الأدوات | `search_knowledge` [query, source, limit] + `list_knowledge` — للأدمن/المالك فقط (ليست في MEMBER_SAFE_TOOLS) |
| القبول | اختبارات: التقطيع والفقرات الطويلة، الترتيب بالصلة، حذف مصدر، عزل الوكلاء |

### 2D. 📊 تتبع الاستخدام + إحصائيات لكل وكيل
| بند | التفاصيل |
|---|---|
| التخزين | مجموعة `agent_usage`: وثيقة لكل {وكيل، سيرفر، يوم} مع $inc — messages / tool_calls / web_calls / provider_calls لكل مزود / fallbacks / errors |
| الربط | hooks في agentRuntime (كل رسالة مستخدم تُعالج) وrunAgent (كل استدعاء أداة، كل تبديل fallback، كل نجاح مزود) |
| الصفحة | زر «الإحصائيات» في صفحة الوكيل: اليوم/7 أيام/30 يوم — رسائل، أدوات (مفصلة top 5)، استدعاءات المزودين، الأخطاء، الإشغال اليومي (مخطط أعمدة نصي) |
| القبول | اختبارات: $inc تصاعدي، فصل الأيام، ملخص صحيح، أمان بدون DB |

### 2E. 🤖 الاستباقية — إصغاء قنوات
| بند | التفاصيل |
|---|---|
| الإعداد | لكل وكيل: `proactive_enabled` + `proactive_channels: [{channel_id, keywords[], cooldown_minutes}]` — من اللوحة |
| العمل | رسالة غير موجّهة له في قناة مُصغاة + تطابق كلمة مفتاحية + انتهاء التهدئة → يُعالجها كمحادثة كاملة (بدون منشن) |
| الأمان | تهدئة لكل قناة (1..720 دقيقة، افتراضي 10)، تجاهل البوتات، لا استباقية في الخاص |
| القبول | اختبار وحدة: مطابقة الكلمات، التهدئة، تجاهل غير المطابق |

### 2F. 🛡️ تشفير التوكنات — AES-256-GCM
| بند | التفاصيل |
|---|---|
| المفتاح | ENV `ENCRYPTION_KEY` (hex 64 أو أي عبارة → اشتقاق scrypt) — بلا مفتاح: تحذير والتخزين كما كان (قابل للتعطيل) |
| الصيغة | `enc:v1:<iv>:<tag>:<data>` — بادئة تُميّز المشفر عن القديم |
| الترحيل | عند الإقلاع: كل التوكنات النصية (discord_token, deepseek_token, qwen_token, openai_api_key) تُشفّر مرة واحدة (idempotent) |
| القراءة | فك شفاف عند كل نقطة استخدام (runtime/لوحة/اختبار اتصال) — العرض دائماً مقنّع ما عدا زر الكشف |
| القبول | اختبارات: roundtrip، عبث بالبيان يُفشل، عبارة pass-through، ترحيل لا يكرر |

## 📏 معايير ثابتة لكل مستوى

1. لا اختراع أصناف جديدة للمزودين — كل شيء عبر عقد providers
2. كل مجموعة Mongo جديدة تُدار من وحدة واحدة (بدون استعلامات مبعثرة)
3. `node --check` لكل الملفات + كل اختبارات المستويات السابقة تمر قبل الدفع
4. توافق قديم إلزامي: وكيل بلا إعدادات جديدة يعمل كما كان حرفياً
5. كل ميزة قابلة للتعطيل (ENV أو إعداد لكل وكيل) — لا إجبار
